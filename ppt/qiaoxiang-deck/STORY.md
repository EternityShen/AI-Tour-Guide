# STORY｜侨乡 · 江门 AI 智能讲解员

## ① 用户意图对齐

- **目标受众**：比赛现场评委 + 观众（含文旅/信息化背景评审）。场合为限时现场展演答辩，随后有评委提问。
- **核心目标**：讲完后评委要相信三件事——① 这不是一个"套壳聊天机器人"，而是能自己看、自己讲、断网也能撑住现场的完整端侧系统；② 技术选择有硬理由（单文件、零 Python、本机多模态、音色统一）；③ 它能被复制到别的展厅，不止江门一个点。
- **PPT 长度**：12 页。按 6–8 分钟陈述设计，Hero 页 3 页（占 25%）。
- **视觉调性**：侨乡旧影 / 灰砖青苔 / 朱砂印泥 / 克制留白 / 纪实摄影。不做科技蓝紫渐变，不做发光粒子。
- **内容边界**：必讲——端侧多模态识图、断网可用与音色统一、单文件零依赖工程数据、六展项知识库。不讲——模型训练细节、内部代码结构、未完成的语音克隆设想（评委追问时口头说明）。禁碰——夸大"官方小伊离线实时合成"，本项目是预录制覆盖，必须如实表述。

## ② 页面布局骨架

12 页，不设目录页（限时答辩，直接进内容），因此无 section 扉页契约负担。分三段：**为什么做（02–04）→ 怎么做到（05–08）→ 凭什么赢（09–12）**。

- 01 封面 — hero
- 02 侨乡的三重困境 — supporting / valley
- 03 我们造了一个"会讲的数字人" — supporting / valley
- 04 六件侨乡事，一套知识库 — supporting / valley
- 05 技术架构：一条端侧链路 — supporting / transition（节奏转场）
- 06 它真的会"看" — supporting / peak（第一个小高潮）
- 07 断网，也还是小伊的声音 — supporting / valley
- 08 六个硬指标 — hero / peak（视觉高潮）
- 09 现场怎么演 — supporting / valley
- 10 与市面方案的正面对比 — supporting / valley
- 11 从一座展厅到一个平台 — supporting / valley
- 12 结束 — hero / peak

Hero 定位：01 封面、08 硬指标、12 结束页，占 3/12 = 25%，两两之间有 ≥1 个 supporting 页。

rhythm 检查：02/03/04 连续三页 valley → 05 为 transition 打破 ✓；06 peak → 07 valley → 08 peak → 09/10/11 valley（三连）→ 12 peak 打破 ✓。

非对称版式预算：02、03、05、06、07、09、10、11 共 8 页为非对称（67% ≥ 40%）✓。其中「左大图+右侧文字」03、06 与「非对称双栏」02、07 合计 4 页 = 33% ≤ 40% ✓。

对称版式预算：仅 04（左标题+右内容属非对称）、08、12 使用对称/居中类，未超过 2 页的"N卡片横排"配额（全篇 0 次）。

### 数据必须落点（逐条核对）
- 170 MB 单文件 → 含义：评委电脑上双击即用，不需要装环境、不需要联网下载依赖，彩排与正式场次表现一致。
- 0 行 Python → 含义：整合包型方案把解释器藏进启动脚本，路径带中文或杀软拦截就崩；原生单进程没有这个故障面。
- 7 秒识图 → 含义：这是"展馆可用"的门槛线，超过 10 秒游客就走了。
- 64 条预置语音 → 含义：覆盖演示与高频问答，是"断网不串音"的物理基础，不是营销数字。
- 34 项测试 → 含义：音频路由、离线守卫、知识库一致性都有回归保护，改一处不会悄悄坏另一处。
